## 总线的基本概念与物理结构
[原片 @ 00:00](https://www.bilibili.com/video/BV1iD68YQER6?t=0)

![](./计算机组成原理-透视版(下)/screenshot_000_9d50dec8-f48c-49ac-888b-0ca1053d4cd1.jpg)
![](./计算机组成原理-透视版(下)/screenshot_001_7df042aa-e1c9-4ad5-a842-15df9a279988.jpg)

CPU 和其他设备之间如果需要传输数据，需要建立电路连线。最初的设计是让各个设备之间两两建立专门的电路连线，但这种方式硬件成本太高。

为了降低成本，可以采用一条公共轨道来替代两两连线。所有设备共享这条轨道，通过分时使用的方式来进行数据共享。

![](./计算机组成原理-透视版(下)/screenshot_002_58252f4b-4974-4d35-8ea1-c90ea74b94c7.jpg)
![](./计算机组成原理-透视版(下)/screenshot_003_cb968885-6ffc-49ac-9010-4c57a25f0342.jpg)

这种共享的工作方式在任一时刻只允许一个设备输出数据，一旦有多个设备同时输出，就会发生冲突。这条用于共享传输的公共轨道就是计算机中的**总线 (Bus)**。

## 总线的类型与结构分层
[原片 @ 00:24](https://www.bilibili.com/video/BV1iD68YQER6?t=24)

![](./计算机组成原理-透视版(下)/screenshot_004_76e8663f-6f68-4c98-9e91-cbe48173560f.jpg)
![](./计算机组成原理-透视版(下)/screenshot_005_e1537a9c-ad13-440b-b27d-feea15c779b2.jpg)

总线根据不同的特性可以分类：
- **按传输方向**：分为单向传输总线和双向传输总线。
- **按传输方式**：分为串行传输总线和并行传输总线。并行传输总线（如图所示的三条轨道）需要更多的硬件线路，成本更高，但速度较快。
- **按所在位置**：分为片内总线和系统总线。
  - **片内总线**：例如 CPU 内部的 ALU 计算器之间使用的总线。
  - **系统总线**：主机各设备间兼容通信使用的总线。

![](./计算机组成原理-透视版(下)/screenshot_006_12595cc3-90dd-4ed9-a3cc-0c383b460173.jpg)
![](./计算机组成原理-透视版(下)/screenshot_007_cf08ab03-e302-41f1-8277-feb5cab03dc6.jpg)

系统总线根据设备连接的拓扑结构，又可分为多种总线结构：
- **单总线结构**：所有设备都共用一条总线。
- **双总线结构**：例如在该结构中，CPU 和主存使用一条总线，其他 I/O 设备用另一条总线。
  - 通过**双端口控制器**，能使其他设备与主存通信。
  - 通过**桥接器 (Bridge)** 连接两条总线，还可以继续增加总线，扩展为**三总线结构**。

![](./计算机组成原理-透视版(下)/screenshot_008_e94062b8-3320-44d8-a0c7-b38d7eea8dc1.jpg)
![](./计算机组成原理-透视版(下)/screenshot_009_7c3f8c41-194b-4df6-97f0-fc371e28bc25.jpg)
![](./计算机组成原理-透视版(下)/screenshot_010_dd9156cf-8314-4965-aea6-15b3d2c62e32.jpg)
![](./计算机组成原理-透视版(下)/screenshot_011_d77458cc-1858-4dc0-8f6c-3f0feec6c631.jpg)

系统总线由三部分组成：
- **数据总线** (Data Bus)
- **地址总线** (Address Bus)
- **控制总线** (Control Bus)

![](./计算机组成原理-透视版(下)/screenshot_012_c6a06a4d-adaf-4fd7-aa6c-87577dd1a2fa.jpg)

为了节省线路，可以使用**总线复用技术**。例如“数据/地址总线复用”，让数据总线和地址总线共用一套物理线路。在前面课程中提到的“组成行列地址复用”就是总线复用技术的一种体现。

## 总线仲裁机制
[原片 @ 01:18](https://www.bilibili.com/video/BV1iD68YQER6?t=78)

![](./计算机组成原理-透视版(下)/screenshot_013_c4b8a767-7d7d-4dc2-8bc7-24abd9b334e4.jpg)
![](./计算机组成原理-透视版(下)/screenshot_014_95b85881-9ebb-49c4-a3e1-4cb55f72f6cd.jpg)
![](./计算机组成原理-透视版(下)/screenshot_015_308c3784-ffed-46c6-936b-1f814439acd6.jpg)

总线是共享资源，如果每个设备都想使用，就需要决定总线的使用权分配。决定总线给谁使用的机制称为**总线仲裁**。常见的仲裁方式有：

### 链式查询
所有设备使用同一个信号请求线。设备需要使用总线时，就“扯一扯”这根请求线。总线控制器收到请求后，将授权信号送给第一位设备。设备自行决定是否使用；如果不需要，就将授权信号传给后面的设备；如果需要，就“扯一扯”忙路线，完成总线占用。

![](./计算机组成原理-透视版(下)/screenshot_016_12d3756d-b858-4d95-a570-9c4620ed2ef5.jpg)
![](./计算机组成原理-透视版(下)/screenshot_017_d48a6aaf-cc00-4b08-9638-2ab9610b5e2e.jpg)
![](./计算机组成原理-透视版(下)/screenshot_018_6a43671f-e392-4c54-8eaa-70298865fc9d.jpg)
![](./计算机组成原理-透视版(下)/screenshot_019_dabdc357-e1b0-4d7a-a50e-b6223c748201.jpg)

总线控制器通过忙路线判断是否有人占用，如果有人占用，后续请求不再授权。这是一种结构简单、线少的设计。但是，由于授权总是按顺序给第一个设备，如果前面的设备一直占用，后面的设备就会一直拿不到总线，发生**“饥饿” (Starvation) 现象**。

![](./计算机组成原理-透视版(下)/screenshot_020_33c27ac0-2158-4876-a686-93dd061b39f6.jpg)

为了解决饥饿问题，可以增加一个**计数器**。每请求一次，计数器增加一，实现**轮流授权**的效果。复杂的计数器还可以实现按优先级授权的效果 (计数器定时查询)。

![](./计算机组成原理-透视版(下)/screenshot_021_6c544497-ce8c-4c2f-9c20-0852fa7e9785.jpg)
![](./计算机组成原理-透视版(下)/screenshot_022_d42f130e-5a36-44d7-93cf-a197d4b59881.jpg)

### 独立请求
每个设备都有自己独立的请求线。总线控制器可以使用 **LRU (Least Recently Used，最近最少使用)** 或 **FIFO (先进先出)** 等算法来决定授权给哪个设备。虽然效率高，但请求线非常多，硬件成本高。

![](./计算机组成原理-透视版(下)/screenshot_023_3d4a1449-a35d-476b-91dd-d12ac779c7b8.jpg)
![](./计算机组成原理-透视版(下)/screenshot_024_fd3a6d95-91cd-456c-a7be-36aafe17831d.jpg)
![](./计算机组成原理-透视版(下)/screenshot_025_72c722e3-bdf4-400e-8ff6-10d01cd08332.jpg)

### 分布式仲裁 (自举分散式)
每个设备都有自己的请求线。请求时，其他设备也能知道哪些设备正在请求。设备通过线“或/线与”逻辑对比，如果自身优先级（仲裁号）大于其他请求的设备，就占用忙路线，其他设备也就知道了当前总线的状态。

![](./计算机组成原理-透视版(下)/screenshot_026_9daba50d-fec7-47b5-a050-f12d4314aaf4.jpg)
![](./计算机组成原理-透视版(下)/screenshot_027_356f9808-b1f1-466e-9b71-f88961911939.jpg)
![](./计算机组成原理-透视版(下)/screenshot_028_5b5f6921-7838-47a5-8092-98e0ff10dfec.jpg)

如果线太多，可以使用**编码的方式**来减少线路。这就是**并行竞争**：每个设备有自己的仲裁号。设备比对每一位仲裁号的大小，如果比总线上已存在的仲裁号大，就修改总线上的仲裁号；否则就表示竞争失败，放弃本次竞争。直到最后总线上的仲裁号与设备的仲裁号一致，说明该设备竞争胜出，可以占用总线。

## 总线传输过程与定时方式
[原片 @ 02:54](https://www.bilibili.com/video/BV1iD68YQER6?t=174)

![](./计算机组成原理-透视版(下)/screenshot_029_3e398f4f-6130-4525-9146-2663bb9ea7a4.jpg)
![](./计算机组成原理-透视版(下)/screenshot_030_8e93788d-73ab-44db-993c-38e4088b3f05.jpg)

总线传输的过程通常包含：
1. **请求** (Request)
2. **寻址** (Addression / Arbitration)
3. **传输** (Transfer)

传输方式支持**突发传输**，即只需要设置一次地址，就能连续读取数据。

![](./计算机组成原理-透视版(下)/screenshot_031_c70d1c0d-164d-4ddb-b3b5-353237a156f4.jpg)
![](./计算机组成原理-透视版(下)/screenshot_032_2f6a831f-4266-4993-ae62-6be7d529f681.jpg)

总线传输时必须处理定时问题：
### 同步定时
最简单的定时方式。主设备和从设备使用**同一个时钟信号**。在时钟的驱动下完成传输，控制简单。

但是，在远距离传送时，同步定时会存在**时钟延迟**的问题。

![](./计算机组成原理-透视版(下)/screenshot_033_2f0074a5-144b-4c2e-a7c7-cd2ffa4ea311.jpg)
![](./计算机组成原理-透视版(下)/screenshot_034_f13cdb81-061a-4e0b-9a36-d468f920ba84.jpg)

### 异步定时
长距离传输通常使用异步定时方式。无统一时钟，靠握手信号交流。
- **非互锁方式**：主设备发出请求信号并维持一段时间，时间一到就断开；从设备收到请求后，发出响应信号，同样维持一段时间后断开。这种方式不依靠对方的应答信号关闭，灵活性差。

![](./计算机组成原理-透视版(下)/screenshot_035_9b150fdd-f01f-4333-850e-f347c8c59e82.jpg)
![](./计算机组成原理-透视版(下)/screenshot_036_82932886-5380-4b21-a279-27e6121d561f.jpg)

- **半互锁方式**：主设备不再使用计时器，而是根据从设备的响应信号来断开请求；而从设备依然使用计时器来决定断开响应信号的时机。

![](./计算机组成原理-透视版(下)/screenshot_037_c1807f11-7b8f-4876-a2b0-999c85d8a108.jpg)

- **全互锁方式**：从设备的计时器也可以去掉，主设备根据从设备的响应信号断开请求后，从设备如果发现主设备的请求信号断了，那就断开响应信号。这种方式也称作全互锁方式。

## I/O 接口与编址方式
[原片 @ 03:54](https://www.bilibili.com/video/BV1iD68YQER6?t=234)

![](./计算机组成原理-透视版(下)/screenshot_038_9706c3fa-fe25-4021-ba4a-11ffb643393e.jpg)
![](./计算机组成原理-透视版(下)/screenshot_039_a3858eb2-1dab-4584-b9c0-35aa9e62cb70.jpg)
![](./计算机组成原理-透视版(下)/screenshot_040_f7eabedc-51b9-4567-b578-49c80882fb1f.jpg)
![](./计算机组成原理-透视版(下)/screenshot_041_de924cb3-246d-4fba-b468-a2d241ccf82b.jpg)
![](./计算机组成原理-透视版(下)/screenshot_042_0035e45c-6bcb-44cf-ae53-70261fe89977.jpg)

CPU 与鼠标、键盘、显示器等外部设备交互，需要输入输出 (I/O) 的支持。外设通过 **I/O 接口**与 CPU 相连。I/O 接口包含：
- **数据缓冲寄存器**：用于缓冲低速的外部设备数据。由于状态使用完后就不再需要了，因此**命令寄存器和状态寄存器可以合并为一个**。
- **状态寄存器**：用于记录状态，方便 CPU 判断并执行下一步。
- **命令寄存器**：用于保存 CPU 发出的命令。
- **地址译码/控制逻辑**：用于解析地址和生成控制信号。

![](./计算机组成原理-透视版(下)/screenshot_043_b1fb3a8f-58af-49de-a5eb-579a8a417e2b.jpg)
![](./计算机组成原理-透视版(下)/screenshot_044_a3487ce6-9f9c-427a-95c0-b4e431fd75ef.jpg)

I/O 的地址如何表示？主要有两种编址方式：
### 统一编址
I/O、主存、磁盘等都共用一套连续的地址。统一编址下，可以把任意设备当成主存来操作，不需要额外硬件和指令。

![](./计算机组成原理-透视版(下)/screenshot_045_07c6a72a-99f7-4748-b485-fb64adb5eed8.jpg)
![](./计算机组成原理-透视版(下)/screenshot_046_3a276720-2076-4302-92ab-355361a29215.jpg)
![](./计算机组成原理-透视版(下)/screenshot_047_ec6ae048-51a3-419c-874d-8ca98911543f.jpg)

### 独立编址
在独立编址下，设备有自己的地址范围，设备间的地址范围可能会重复。因此需要**额外的指令**来区分主存操作还是 I/O 操作。例如 x86 汇编中，使用特定的指令（如 IN/OUT）来做 I/O 读写操作。在硬件中，也需要在总线中使用不同的信号线来区分当前地址表示的地址类型。

## 程序查询与中断交互方式
[原片 @ 04:54](https://www.bilibili.com/video/BV1iD68YQER6?t=294)

![](./计算机组成原理-透视版(下)/screenshot_048_86185c2d-b2ce-4eae-b65a-c40b2fc92438.jpg)
![](./计算机组成原理-透视版(下)/screenshot_049_cab927e5-5a64-409d-b748-00c424f50ed1.jpg)

解决了地址问题，就可以使用**程序查询**的方式来交互。CPU 根据状态寄存器判断设备数据是否准备完毕。一旦完成，就可以将数据缓冲寄存器的数据移入 CPU 使用。

![](./计算机组成原理-透视版(下)/screenshot_050_1d3d6d59-2f22-48af-9929-571ddd8bd314.jpg)
![](./计算机组成原理-透视版(下)/screenshot_051_6ba9dbaa-30a7-4f2c-a020-d4d567c2d135.jpg)

**独占查询**：简单理解就是“同步阻塞”的方式。CPU 命令发出后，停止执行，等待设备的响应。由于 CPU 需要独占等待，因此存在效率问题。

![](./计算机组成原理-透视版(下)/screenshot_052_09d25801-8e6d-4cd2-9a74-dca425c8a01c.jpg)
![](./计算机组成原理-透视版(下)/screenshot_053_22c58c67-fc3c-4955-b897-13778079745a.jpg)

**轮询请求**：为了提高效率，CPU 发出请求并不一直等待设备，如果没有得到响应，立马离开，一定时间间隔后再来，直到响应为止。轮询虽然能提高效率，但是由于需要频繁请求，容易造成浪费。

![](./计算机组成原理-透视版(下)/screenshot_054_f0278329-78be-4010-9e78-e1590d737819.jpg)
![](./计算机组成原理-透视版(下)/screenshot_055_c811e1a2-3d32-4270-bce4-7000265f9000.jpg)

因此可以使用**程序中断**的方式。回顾上集指令执行过程，一条指令是由 PC 决定的，修改 PC 的值，就能实现程序的跳转。汇编中调用函数本质就是修改 PC，执行完后再恢复 PC。

![](./计算机组成原理-透视版(下)/screenshot_056_f5694ec1-ba88-40f9-b800-787803756fef.jpg)
![](./计算机组成原理-透视版(下)/screenshot_057_dc71026e-4f44-4117-a469-4a16cfce25f9.jpg)
![](./计算机组成原理-透视版(下)/screenshot_058_58e3fb1e-2a02-43b3-9ab0-a58b9bcb6daa.jpg)

程序中断就是一种特殊的函数调用，不同的是：函数调用是可以提前预知的，而程序中断是无法预知的（例如鼠标输入）。因此需要由设备发起中断请求，根据入口地址找到对应的中断程序地址并跳转执行。

## 中断处理完整流程
[原片 @ 06:00](https://www.bilibili.com/video/BV1iD68YQER6?t=360)

![](./计算机组成原理-透视版(下)/screenshot_059_f17c25d4-9de0-4f8c-9f53-021355375895.jpg)
![](./计算机组成原理-透视版(下)/screenshot_060_edf3b4fe-4ab7-4d92-b18d-843bc00770bc.jpg)

### 非向量中断
所有中断请求的入口地址都是同一个“中断查询程序”入口。具体应该执行哪一段中断程序，由中断查询程序（软件）决定，因此也称作**软件查询方式**。

![](./计算机组成原理-透视版(下)/screenshot_061_62eaac0b-395c-4459-8681-a6957d3d5e9c.jpg)
![](./计算机组成原理-透视版(下)/screenshot_062_1a984220-78ef-4da1-aea5-386567b3f0a6.jpg)
![](./计算机组成原理-透视版(下)/screenshot_063_0026b970-e36f-44a9-b81f-80ca4b4842b0.jpg)
![](./计算机组成原理-透视版(下)/screenshot_064_de3ec2c9-1382-466d-bb61-9d1bd79a03f1.jpg)

### 向量中断 (硬件中断)
向量中断过程中，硬件直接介入处理。
1. **中断请求**：设备发起中断请求。可以使用独立请求方式，或共享请求线的链式请求方式。
2. **中断屏蔽器**：请求信号会经过中断屏蔽器（本质是一个寄存器），用于决定哪些设备现阶段不允许发出中断请求。
3. **排队器**：之后请求信号经过优先排队器进入 CPU。这些信号又称作**可屏蔽中断源**。

![](./计算机组成原理-透视版(下)/screenshot_065_bfb12826-39da-4565-b4c9-174e96de321f.jpg)
![](./计算机组成原理-透视版(下)/screenshot_066_0e727a60-c023-4189-b21c-8cebdf5e322c.jpg)

与之相反的是**不可屏蔽中断源 (NMI)**，例如电源挂起/系统崩溃通知等，它不受中断屏蔽器的控制。这些信号经 CPU 判断后，得出响应信号，进入中断响应阶段。

### 中断响应
1. **关闭中断**：防止中断程序执行过程中，其他中断请求进来。
2. **保存断点**：也就是保存 PC 的值，和函数调用的过程是类似的。
3. **中断识别**：找中断程序的入口地址。每个中断源有自己的**中断号**（是一个索引值）。用中断号算出向量地址，在**中断向量表**中找到记录，根据记录值得出中断程序的入口地址，将 PC 的值改为入口地址，实现中断程序调用。

![](./计算机组成原理-透视版(下)/screenshot_072_c1b0b7f9-a80f-4ac1-8b83-d5298c40c134.jpg)

![](./计算机组成原理-透视版(下)/screenshot_074_85618bad-41d9-42a3-9639-e7c75064d8e8.jpg)

### 执行中断服务程序
1. **保护现场**：执行前需要将正在使用的寄存器内容入栈，防止中断程序执行完毕恢复后，原本的程序无法正常继续。
2. **执行中断程序指令**。
3. **恢复现场**：执行完恢复现场也就是寄存器内容出栈。
4. **开中断**：允许其他中断请求被响应。
5. **恢复 PC**：返回到原程序断点处继续执行。这就是程序中断的完整过程。

### 多重中断
允许在中断处理过程中，插入另一个更高优先级的请求。
实现多重中断需要：
1. 在中断程序执行前设置**中断屏蔽字**，来决定允许哪些中断源插队。
2. 设置好后**开中断**。
3. 中断程序执行完后**关中断**，并且**恢复现场**后，需要**恢复中断屏蔽字**，并发出**中断结束信号**。
多重中断其实就是在中断服务程序内部嵌套调用另一个中断处理程序的过程。

## DMA 直接内存访问方式
[原片 @ 07:54](https://www.bilibili.com/video/BV1iD68YQER6?t=474)

![](./计算机组成原理-透视版(下)/screenshot_078_98e1ea87-89d5-4dc1-8231-459b0c5e8ffb.jpg)
![](./计算机组成原理-透视版(下)/screenshot_079_67bf4430-6538-4c45-95ab-1af975b3cdb5.jpg)
![](./计算机组成原理-透视版(下)/screenshot_080_2b14d2af-a3e1-4407-836f-50f0628070e2.jpg)

上述的中断传输方式都需要消耗 CPU 的时间进行数据搬运。如果指令一部分是访存指令，另一部分可能是计算指令，访存期间 CPU 处于等待状态，效率不高。
因此可以加入 **DMA (Direct Memory Access，直接内存访问)**，来分担 CPU 的访存工作。CPU 通过给 DMA 发出命令，之后就可以不用管了，继续执行指令。

![](./计算机组成原理-透视版(下)/screenshot_081_07316b15-6a5e-4a1b-8688-1fefcd6ea4c6.jpg)
![](./计算机组成原理-透视版(下)/screenshot_082_9e26797d-9fb7-429d-9387-1e2b611b3528.jpg)

但是，CPU 和 DMA 都连接了主存，如果同时访问，就会造成结果冲突。对此有多种解决方案：
### 停止 CPU 方式
DMA 执行时，CPU 禁止使用总线。但这样又退化成类似非 DMA 的方式了，效率极低，没有发挥出 CPU 的独立计算能力。

![](./计算机组成原理-透视版(下)/screenshot_083_5d53828e-229d-42b6-84f4-70d42fccb07d.jpg)
![](./计算机组成原理-透视版(下)/screenshot_084_925e0107-e1c4-48e5-99ac-85b7ecc0328b.jpg)

### 交替访问方式
按访存周期实行“单双号限行”，例如 CPU 单号出行（访问），DMA 双号出行。但是这种机械式的划分也同样造成资源浪费。

![](./计算机组成原理-透视版(下)/screenshot_085_aaf56e31-7b6d-4008-89b9-5b2f9db308e9.jpg)
![](./计算机组成原理-透视版(下)/screenshot_086_c7bdee6a-4ff3-4448-8ef7-cbe2f054dbd1.jpg)

### 周期挪用方式
按访存周期进行划分，**优先给 DMA 使用，DMA 不使用再让 CPU 使用**。周期挪用方式与停止 CPU 方式的区别在于，周期挪用更灵活，且可以做到让计算和数据传输并行，可以效率最大化。这种优化思想在很多效率优化场景中都有体现。
