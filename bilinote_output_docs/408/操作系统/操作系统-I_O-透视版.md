- **磁盘物理结构**：主要由盘片和磁头组成。
- **盘片与磁道**：盘片上布满不同半径的若干磁道，放大后可以看到盘片布满极微小的磁颗粒。若干个颗粒组成一个磁畴（相当于微型磁铁），通过磁化方向表示数据 `0` 和 `1`，实现数据的读写。
- **扇区结构**：每个磁道由若干个扇区组成。扇区由**扇区头**（地址标识）、**同步信息**（定位扇区）、**数据区**（保存用户数据）、**校验信息**（检错纠错）组成。
- **内外圈差异**：在同一个盘片里，外圈磁道的扇区长度大于内圈扇区的长度，但它们所表示的数据量相同。这是由于磁盘采用 **CAV (恒定角速度)** 模型，保持同步旋转。
- **盘面与磁头**：盘片的一个面称为一个盘面（最多两个盘面）。每个盘面搭配一个磁头进行数据读写。
- **多盘片结构**：可将多个盘片组合成多盘片磁盘。所有磁头固定在同一个磁头臂上，做径向同步移动；所有盘片固定在同一个主轴上，由电机驱动，以完全相同的角速度同步旋转。

- **柱面（Cylinder）**：每个盘面上**相同半径磁道**的集合称为柱面。从柱面视角展开，可以看到磁盘的数据结构由多个柱面组成，每个柱面包含多个磁道，每个磁道对应一个盘面号，每个磁道包含多个扇区。
- **确定位置**：
    - 通过**柱面号**确定磁道集合。
    - 通过**盘面号**（磁头号）定位具体磁道。
    - 通过**扇区号**确定磁道的某一段区间。
    - 这三部分（柱面号 + 盘面号 + 扇区号）组成了一个完整的**磁盘地址**。
- **数据读取流程**：根据柱面号寻道，移动磁头臂到对应柱面位置 -> 选择对应的盘面号磁头 -> 等待对应扇区旋转到磁头下方 -> 旋转读写数据。

- **访问时间公式**：$$T_a = T_s + T_r + T_t$$
    - $$T_s$$：寻道时间
    - $$T_r$$：旋转延迟
    - $$T_t$$：传输时间
- 假设转速为 $$R$$，扇区数为 $$N$$：
    - 平均旋转延迟：$$\frac{1}{2R}$$
    - 传输一个扇区的时间：$$\frac{1}{RN}$$
    - 这两个时间受限于硬件机械结构，软件难以优化。可优化的是**寻道时间**，主要由磁盘调度算法决定。

### 经典磁盘调度算法

- **FCFS（先来先服务）**
    - 磁头从当前位置按请求顺序依次调度。不考虑局部性，磁头移动距离大，性能较差。

- **SSTF（最短寻道时间优先）**
    - 磁头优先访问距离当前磁头位置最近的磁道。
    - **缺点**：如果大量请求集中在某个范围，磁头会一直在这个范围活动，导致其他范围请求长时间得不到响应，即**饥饿**现象。

- **SCAN（扫描算法/电梯算法）**
    - 磁头像雨刮器一样，在最小序号磁道和最大序号磁道来回扫描，遇到请求就处理。
    - 没有饥饿问题，但如果请求集中在局部，仍需要扫描完全部磁道，造成浪费。

- **LOOK 算法**
    - 改进的扫描算法，磁头到达最远请求磁道后立即折返，而不是走到物理边界，减少无效空跑。
    - 数据双向读取。但在访问大序号和小序号磁道请求时，等待时间不均。

- **C-LOOK（循环 LOOK）**
    - 单向读取数据（比如只往大序号方向），折返时空车快速返回起点。
    - 像扫地一样，扫过去后提起来回到初始位置，再继续扫。

- **C-SCAN（循环扫描）**
    - 磁头从一端往另一端扫描，抵达终点后空车折返，然后进行第二轮扫描。
    - 结合了 SCAN 全局范围和 LOOK 的单向处理特点。

- **设备控制器**：CPU 直接与外设对话速度会被严重拖累。因此引入**设备控制器**作为代理人（包含控制寄存器、状态寄存器、数据寄存器、控制逻辑）。
- **I/O 控制方式演进**：
    - **轮询（Programmed I/O）**：CPU 向控制器写命令后，一直循环读取状态寄存器等待数据就绪，占用 CPU 无法处理其他任务。
    - **中断驱动**：CPU 写命令后去执行其它进程。数据就绪时，控制器发出**中断信号**，CPU 执行完当前指令后响应中断。但数据搬运工作仍由 CPU 全程参与，占用大量性能。
    - **DMA（直接内存访问）**：为解决 CPU 参与搬运的问题，引入 DMA 控制器。CPU 只需告知数据从哪里搬到哪里、搬多少，即可离开。DMA 申请总线控制权后，直接在不需 CPU 参与的情况下将数据从寄存器搬运到内存。搬运完成后发中断通知 CPU。
        - 限制：DMA 逻辑由硬件决定，只能搬运连续的数据块。对于复杂的分散/聚集搬运，需要 CPU 多次下达指令，频繁中断影响性能。
    - **通道方式（Channel I/O）**：使用**通道处理器**（可理解为低性能 CPU），与 DMA 不同的是通道处理器可以执行程序。CPU 可将复杂的搬运规则写成通道程序放入内存，并把这段程序的指针告知通道处理器，通道处理器自行执行搬运，CPU 并行处理其他任务。现代个人计算机很少使用，多用于大型机。

- **层次划分**：
    - **用户层 I/O 软件**：包含标准库（如 `open`、`printf`、`fread` 等）。
    - **设备独立软件**：提供设备分配、缓冲管理、SPOOLing 等通用功能。
    - **设备驱动程序**：屏蔽具体硬件细节，直接与设备控制器对接。
    - **中断处理程序**：最底层，处理硬件中断。
- **设备分配数据结构**：
    - **DCT（设备控制表）**：记录设备状态、物理设备名、控制器指针。
    - **COCT（控制器控制表）**：记录控制器状态、通道指针。
    - **CHCT（通道控制表）**：记录通道状态。
    - **SDT（系统设备表）**：记录所有设备的设备类型、物理设备名及 DCT 指针。
- **逻辑设备表（LUT）**：
    - 用于解决设备物理拔插导致进程申请失败的问题。
    - 记录**逻辑设备名**与**物理设备名**的映射。进程使用逻辑设备名申请，系统转换为物理名。设备损坏时只需修改 LUT 中的映射关系即可，实现程序与具体硬件的解耦。为防止同名冲突，可为每个进程设置单独的 LUT。

- **目的**：减少 CPU 与外设速度不匹配带来的等待时间。
- **单缓冲**：
    - 外设输入数据到缓冲区（耗时 $$T$$），从缓冲区移动到工作区（耗时 $$M$$），CPU 从工作区处理数据（耗时 $$C$$，类似喝完饮料需要的时间）。
    - **耗时计算**：第 1 块需耗时 $$T + M + C$$。从第 2 块开始，传输和处理可以并发执行。耗时计算取决于瓶颈：若 $$T > C$$，瓶颈在传输；否则瓶颈在 $$C$$ 或 $$M$$。
    - 汇总公式：第 1 块为 $$T + M + C$$，后续每块为 $$\max(C, T) + M$$。
- **双缓冲**：
    - 增加一个缓冲区，当一个缓冲区移动数据时，另一个缓冲区同时写入数据。
    - 瓶颈取决于 $$T$$ 和 $$M+C$$ 的大小：
        - 若 $$T > M+C$$，瓶颈在 $$T$$，后续每块耗时为 $$T$$。
        - 若 $$T < M+C$$，瓶颈在 $$M+C$$，后续每块耗时为 $$M+C$$。
    - 汇总公式：第 1 块为 $$T + M + C$$，之后每块为 $$\max(T, M+C)$$。
- **缓冲池**：
    - 多个缓冲区循环使用，所有设备共享，解决资源闲置。
    - 包含队列：**空闲缓冲队列**、**输入缓冲队列**、**输出缓冲队列**。
    - 外设输入时从空闲队列取空杯，装满放入输入队列，然后等 CPU 来消费
    - CPU 输出时从空闲队列取空杯，装满放入输出队列，等待外设来取。

- **场景**：针对打印机等**独占设备**（一次只能给一个进程使用）的问题，提高各进程的打印体验（避免进程一直守着打印机等待）。
- **原理**：（以输出井为例讲解，输入井类似）
    - 增加一个磁盘区域（**输入井**和**输出井**），类似一个“箱子”。
    - 进程需要打印时，将这些进程需要打印的文件放入箱子（输出井）装起来，收集好后，这些进程就可以完成了，剩下的事交给守护进程处理。
    - **守护进程**从箱子（输出井）中一次取出文件，交由打印机（外设）处理，从而提高各进程的打印体验。
- **本质**：SPOOLing（Simultaneous Peripheral Operations On-Line）本质上是一种**持久化的异步队列技术**。
