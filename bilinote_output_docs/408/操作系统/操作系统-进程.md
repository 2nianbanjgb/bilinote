## 进程与死锁的由来
[原片 @ 00:00](https://www.douyin.com/video/7589335472145501481)

![](./操作系统-进程/screenshot_001_90a5c44f-ddb1-4ad1-8c10-264396bdfcc5.jpg)

- **厨房模型**：操作系统就像厨房，CPU是灶台，ALU相当于锅，寄存器相当于碟子。
- **资源申请冲突**：小红申请了菜刀，小黑申请了砧板。小红还需要砧板，小黑还需要菜刀。
- **死锁（Deadlock）**：小红缺的砧板在小黑那里，小黑缺的菜刀在小红那里，双方循环等待，导致所有人停止工作，这就是进程的死锁现象。

## 进程的定义与组成
[原片 @ 00:30](https://www.douyin.com/video/7589335472145501481)

![](./操作系统-进程/screenshot_002_a8548d98-b4d0-48c1-917d-548c52596613.jpg)

- **多道程序系统原理**：程序执行时将数据放入寄存器。若有其他程序插队，就把数据保存并切换程序，让出 CPU，从而实现程序的快速切换与并发执行。
- **进程的概念**：为了方便管理，系统将程序运行时的数据打包成一个管理单元，这就是进程（Process）。
- **进程的组成部分**：
  - **数据段（Data Segment）**：存放全局变量和常量。
  - **代码段（Code Segment）**：存放程序代码。
  - **栈（Stack）**：一种数据结构，像一叠盘子，用于存放局部变量和函数参数（入栈/出栈操作）。
  - **堆（Heap）**：一大块内存空间，通常用于存放程序实例对象（动态分配内存）。

## 进程控制块与状态
[原片 @ 01:24](https://www.douyin.com/video/7589335472145501481)

![](./操作系统-进程/screenshot_003_4420c559-3985-40a2-8c66-a886055f6ed0.jpg)

![](./操作系统-进程/screenshot_004_39da7443-67df-4463-ab13-ab433a51c26e.jpg)

- **进程控制块（PCB）**：用来登记管理上述所有进程信息的数据结构。主要内容包括：
  - **进程标识符**：进程 ID（PID）、父进程 ID（PPID）、用户 ID（UID）。
  - **进程状态**：如运行态。
  - **CPU 现场信息**：指令指针（PC）、栈指针（SP）、寄存器信息等。
  - **进程调度信息**：优先级等。
  - PCB 的创建意味着一个进程的创建。

- **进程的状态**：
  - **创建态（New）**：进程正在被创建，系统分配内存等资源。
  - **就绪态（Ready）**：资源分配完成，等待 CPU 调度。
  - **运行态（Running）**：被调度系统选中，独占 CPU 执行。如果是多核处理器，则可以多个进程同时处于运行态。
  - **阻塞态/等待态（Blocked/Waiting）**：运行态进程需要等待 IO 资源（如打印机）或某些事件，主动放弃 CPU。
  - **终止态（Terminated）**：进程正常结束、异常退出或被强制终止。
- **状态转换**：就绪态 -> 运行态（调度选中）；运行态 -> 就绪态（时间片用完/被高优先级抢占）；运行态 -> 阻塞态（等待资源）；阻塞态 -> 就绪态（资源准备就绪）。

## 线程的概念与分类
[原片 @ 03:00](https://www.douyin.com/video/7589335472145501481)

![](./操作系统-进程/screenshot_008_b0882cfc-82c4-4fb5-bb7f-96441baa9db6.jpg)

![](./操作系统-进程/screenshot_009_4627ca51-bdec-4a18-b218-80a03dda7fc2.jpg)

- **并发与顺序**：没有进程概念时，程序顺序执行（如先做番茄炒蛋再做佛跳墙）。有了进程后，交替使用 CPU，可能出现交叉执行。多核 CPU 可以真正的并行执行多个进程。
- **IO 阻塞与 CPU 利用率**：程序指令顺序执行时，若遇到 IO 等待（如水龙头没水），后面的程序无法执行，即使 CPU 空闲也会被浪费。
- **用户级线程**：把程序切碎，将需 IO 的操作分成申请、执行、释放三个阶段，并通过循环取模等方式轮流执行不同函数。对用户来说像是同时执行，但这本质只是调整指令执行顺序，分配到一个 CPU 核心上，无法利用多核。
- **内核级线程**：由操作系统内核直接调度和管理。可以将多个线程并行分发到不同的 CPU 核心上真正并行执行。
- **线程的定义**：有了线程后，进程用作操作系统分配资源的最小单位，而线程用作 CPU 调度的最小单位。
- **线程控制块（TCB）**：用于登记线程信息，内容主要包括进程 ID、线程 ID、调度状态、优先级等。

## 单处理器调度策略
[原片 @ 05:00](https://www.douyin.com/video/7589335472145501481)

![](./操作系统-进程/screenshot_013_f2a76d90-afab-451a-9ac1-475cc4c72e8e.jpg)

- **先来先服务（FCFS）**：按到达顺序排队依次使用 CPU。缺点是如果前面的线程耗时特别久（长作业），后面的短作业将等待过长（类似排队上厕所，前面的人闹肚子导致所有人等待）。
- **最短作业优先（SJF）**：让耗时短的作业排在前面。分为**非抢占式**（当前线程运行完才切换）和**抢占式**（新线程到来时，如果所需时间更短，立即抢占 CPU）。
- **最短剩余时间优先（SRTN）**：SJF 的抢占式版本，决策时比较剩余时间。缺点是如果不断有短作业插入，排在后面的长作业会永远排不到前面，产生**饥饿（Starvation）**现象。
- **最高响应比优先（HRRN）**：为了避免饥饿，引入响应比。公式如下：
  $$
  R = \frac{等待时间(W) + 预估运行时间(T)}{预估运行时间(T)} = 1 + \frac{W}{T}
  $$
  通过等待时间占比反映“痛苦程度”。短作业稍微等一下就“很痛苦”，长作业可以忍受久一点。系统按响应比从大到小调度，兼顾了短作业和长作业。

![](./操作系统-进程/screenshot_014_6e132fcf-8c32-417d-86de-5d2d63a95328.jpg)

![](./操作系统-进程/screenshot_015_dc31310f-9518-48b0-a33c-ac89646547a2.jpg)

![](./操作系统-进程/screenshot_016_5c390a5c-4ffd-447e-b6ed-16a94b731ac4.jpg)

![](./操作系统-进程/screenshot_017_ed189f3a-1dbc-4fc6-a639-921cebbaf3c1.jpg)

- **时间片轮转（RR）**：在 FCFS 基础上限定每个线程使用 CPU 的时间（时间片）。用完强制剥夺，排到队尾。这种算法不会产生饥饿。
- **优先级调度（Priority Scheduling）**：按优先级高低排队。为了防止低优先级作业饥饿，可以采用**动态优先级**机制（运行期间动态调整优先级）。
- **多级队列（MLQ）**：将任务分类（如实时、分时、批处理，优先级由高到低），等级越高的优先执行。等级内可以使用时间片轮转，如果在消耗过程中高等级的队列有新线程进入，那么会立即回到高等级队列处理。这种分配通常是人为安排的。
- **多级反馈队列（MLFQ）**：任务的等级不固定，根据表现动态调整。时间片用完则降级（说明它作业时长超过了这个等级的时间片，耗时超标），没用完则升级（表现优异）。这是目前最常用的调度算法之一。

## 多处理器调度策略
[原片 @ 08:48](https://www.douyin.com/video/7589335472145501481)

![](./操作系统-进程/screenshot_022_a895fabb-868e-41cb-aaee-d11f847ec31c.jpg)

- **调度目标**：负载均衡（防止忙闲不均）、缓存亲和性（尽量让同一线程在同一个核心执行，提高 Cache 命中率）、减少同步开销（降低核心之间的锁竞争）、扩展性（吞吐量应该随核心数成倍增加）。
- **对称多处理（SMP）**：所有 CPU 核心共享同一个就绪队列。需锁机制避免争抢。可以通过软亲和（调度器尽量分配同一核心）或硬亲和（代码指定核心）来提高缓存亲和性。
- **私有就绪队列调度**：每个核心有独立的任务队列。调度器定时盘查各核心情况，将繁忙队列的任务分给空闲队列，或者在空闲时从其他核心“偷”任务来执行。

## 软件层面的互斥实现
[原片 @ 11:18](https://www.douyin.com/video/7589335472145501481)

![](./操作系统-进程/screenshot_028_545c68d6-cc31-4914-81e6-ae1eeca2226a.jpg)

- **单标志法**：一个全局标志位（蓝/红）。A 进入前检查标志，若为对方状态则死循环等待，执行完翻转标志。缺点是必须严格交替执行，若 B 一直不使用，A 会被卡死进去不了。
- **双标志先检查法**：各自有独立标志位。检查对方未上锁，则自己上锁并进入。缺点是检查与上锁两步之间存在间隙，可能导致同时检查并同时上锁，同时进入临界区。
- **双标志后检查法**：先上锁再检查对方。缺点是可能同时上锁并同时检查到对方上锁，然后同时等待，导致死锁（或饥饿）。
- **Peterson 算法**：双标志后检查法 + 单标志法的组合。先将自己的标志设为红色表达意愿，再检查对方意愿，如果对方不想进，则直接进入。若同时想进，则通过“竞争标志”来最终决定谁进入。

![](./操作系统-进程/screenshot_029_70004ff2-0b2a-4840-a3cd-76b457f9643b.jpg)

![](./操作系统-进程/screenshot_030_a28750f7-f3aa-44a1-8cf3-5ff7e0b30232.jpg)

![](./操作系统-进程/screenshot_031_04cf1452-318b-429b-be47-78903ab4e15f.jpg)

![](./操作系统-进程/screenshot_032_40966c3d-cd8c-44ef-86c4-1eb27304cbf9.jpg)

![](./操作系统-进程/screenshot_033_843d7235-aeab-4abd-8a2f-74dd8e1a1149.jpg)

- **Lamport 面包店算法**：用于解决 N 个线程的互斥问题。分为两步：1. 取号（各线程获取一个编号）；2. 比号（根据号码排队，最小的优先，相同时根据线程 ID 排序进入）。非常优雅地解决了多线程互斥。

## 硬件层面的互斥实现
[原片 @ 15:06](https://www.douyin.com/video/7589335472145501481)

![](./操作系统-进程/screenshot_035_f33dd238-db14-4489-ba7f-2e2f714428f0.jpg)

- **中断屏蔽**：关闭中断以防止进程切换。但这会导致 CPU 变成单进程执行，性能极差。
- **原子指令（XCHG）**：提供硬件层面的原子命令（如 x86 的 XCHG），在一个指令内完成读取和写入，解决了读写分离被插队的问题。

    `````py
    x86 提供了 XCHG（exchange，交换）这类指令。
    它的关键特性是："读旧值 + 写新值"在一条指令内完成，中间不可被打断。
    XCHG reg, mem 的语义是：把寄存器的值和内存的值互换。对内存而言，它一次性完成了"读出旧值"和"写入新值"。
    因为是一条指令，CPU 保证它原子执行（在单核上不会被中断切开；在多核上，x86 的 XCHG 带隐式 LOCK 前缀效果，会锁总线/缓存行，保证其他核看不到中间状态）。
    `````

- **Test-and-Set（TSL）**：悲观锁模式，先上锁后操作。通过交换指令将 1 写入锁变量，若旧值等于 0 则上锁成功；否则自旋等待。
- **Compare-and-Swap（CAS）**：乐观锁模式。不上锁，而是进行“比较并交换”。写入时带着预期值，如数据版本一致则成功，不一致失败重试，可减少锁的等待时间。在数据库的乐观锁（如 SQL 中 `WHERE version = 5`）中非常常见。

## 信号量与经典同步问题
[原片 @ 17:24](https://www.douyin.com/video/7589335472145501481)

![](./操作系统-进程/screenshot_039_41b5d778-7fd0-4a3d-a2be-afe4f2a68e76.jpg)

![](./操作系统-进程/screenshot_040_cbc575af-240d-46b2-8061-2c9e25c80ba9.jpg)

- **信号量（Semaphore）**：一种用于解决同步和互斥问题的计数器变量数据结构，包含一个计数器（资源数量）和一个等待队列（用来存放休眠的进程）。
- **P 操作**：借资源。信号量减 1，若小于 0，把当前线程压入等待队列。
- **V 操作**：归还资源。信号量加 1，若小于等于 0，则唤醒等待队列中的线程。
- **生产者消费者问题**：
  - 有固定容量的缓冲区，生产者写入，消费者读取。
  - 不能同时读写，也不能同时写。
  - 定义三个信号量：`empty`（空位信号量，初始为缓冲区大小）、`full`（满位信号量，初始为 0）、`mutex`（读写锁信号量，初始为 1）。
  - **生产者**：P(empty) -> P(mutex) -> 写入数据 -> V(mutex) -> V(full)。
  - **消费者**：P(full) -> P(mutex) -> 读取数据 -> V(mutex) -> V(empty)。

![](./操作系统-进程/screenshot_041_c17efa97-4a3b-4d3d-a404-5f17087666e2.jpg)

![](./操作系统-进程/screenshot_042_6abf5c62-6361-48e1-842e-1f1d35f3283c.jpg)

![](./操作系统-进程/screenshot_043_6a36e16e-fdae-4731-9030-4da55b46e02d.jpg)

![](./操作系统-进程/screenshot_044_df043d79-67e5-4c5c-9ac3-48f865ef103f.jpg)

- **读者写者问题**：
  - 允许多个读者同时读，但读写、写写操作互斥
  - 定义一个互斥信号量 `mutex`
  - **写者**：P(mutex) -> 写数据 -> V(mutex)
  - **读者**：第一个读者需要 P(mutex) 上锁，后续读者发现前面有人，直接“跟风”进入读取，不加锁。最后一个读者读完离开时 V(mutex) 解锁

## 死锁的产生与预防
[原片 @ 20:18](https://www.douyin.com/video/7589335472145501481)

![](./操作系统-进程/screenshot_046_6284e91a-dd77-4845-8aeb-f07585b2a6a0.jpg)

- **死锁（Deadlock）**：多个进程互相持有对方需要的资源并无休止地等待。
- **产生死锁的四个必要条件**（破坏任意一个即可破除死锁）：
  - **互斥（Mutual Exclusion）**：资源只能被一个进程占用。破坏方法：如 SPOOLing 技术（虚拟化独占设备为共享队列）。
  - **占有且等待（Hold and Wait）**：拿着一个资源，又等待另一个。破坏方法：一次分配打包所有资源（缺点是利用率低）。
  - **不可抢占（No Preemption）**：拿到的资源不能被强行剥夺。破坏方法：允许强行剥夺（缺点是容易导致执行混乱）。
  - **循环等待（Circular Wait）**：进程间形成循环等待。破坏方法：固定好资源的申请顺序（如必须先申请菜刀再申请砧板）。

- **银行家算法（Banker's Algorithm）**：用于**死锁避免**。在资源分配前进行安全性检查。
  - 每个进程声明最大需求量。
  - 当进程申请资源时，系统先“尝试”分配，然后检查是否存在一条安全序列，能让所有进程顺利执行完毕并释放资源。
  - 如果存在安全序列（如 C 完成释放资源 -> B 执行完释放 -> A 执行完释放），则同意申请；否则拒绝申请。

## 进程的通信方式
[原片 @ 23:36](https://www.douyin.com/video/7589335472145501481)

![](./操作系统-进程/screenshot_053_cc1b8cab-69f8-41d3-bdd2-4ba06931a866.jpg)

![](./操作系统-进程/screenshot_054_95f23332-fd19-4f44-b64f-a0c78d2dd63d.jpg)

- **共享内存**：操作系统把同一块物理内存映射到不同进程的虚拟地址空间中，进程直接读写。
- **管道**：内存中开辟的一段固定大小的缓冲区，半双工（数据只能单向流动）。
- **消息传递**：
  - **直接通信**：发送者明确指定接收者（像写信）。
  - **间接通信**：把消息发到信箱/消息队列，接收者自己去取。
- **信号（Signal）**：用于通知某个事件发生。例如键盘按下 `Ctrl + C`，内核会发送终止信号，仅传递数字信号，不传递复杂数据。
